# Character creation from a photo: 504 at the 15 s gateway limit

**What happened.** On https://conquest.cnh.radarhq.io, "Create from my photo" always showed "Character creation isn't available right now. Your current character is safe."

**What we found.** Reproduced from the live page with Claude in Chrome. A bad photo sent to `POST /api/characters` came back 200 `invalid_photo`, so routing and the origin check worked. A real 256×256 JPEG came back **504 `upstream request timeout` (text/plain) after 15.0 s**. That reply comes from the platform gateway, not our app. The route waited on one OpenAI image edit (`gpt-image-2`, 1024², medium), which takes about 65 s, and the client shows that message for any status that isn't a success. It's the same 15 s proxy limit as the check-in writes (DECISIONS.md, G.R3). We can't change the gateway (`deploy/httproute.yaml` is inert), and `maxDuration = 200` had no effect.

**Root cause.** A slow call made in a single request behind a 15 s gateway.

**Fix.** POST now starts an OpenAI Responses **background** job (image_generation tool, `gpt-image-2`) and returns a signed job token that expires after 10 minutes. The browser calls `GET /api/characters?job=…` every 3 s. OpenAI holds the job, so either of the 2 web replicas can answer. A local run against OpenAI: start 4.1 s, each check ~0.3 s, finished sheet after 65.6 s (19 checks). PR: _see branch `jake/character-timeout`_.
