# 040: Web

Status: Accepted
Prefix: `WEB`
Lane: Web
Owner: Danny

## Purpose

Everything people see: the organizer's setup and live view, the attendee's signup, dungeon map, XP actions and recap, and the speaker's recognition page. Mobile first (attendees are on phones), with the organizer and leaderboard views made for a laptop or a hallway monitor. It carries the **Merge Forward** track: the map must work for screen-reader users, keyboard users, and people who need step-free routes. It sends browser telemetry (RUM) to Dash0.

## Non-goals

- Required login or account authorization. Optional LinkedIn sign-in imports the attendee's name/photo; the attendee id remains in localStorage and the organizer page remains open by URL.
- Native app, offline mode, push notifications.
- Uploading or storing photos taken for XP (the camera capture awards XP and stays on the device). The profile photo is the one exception (below).
- Scraping LinkedIn profiles. Import only the consenting member's name/photo through official OpenID Connect; profile links, headlines and about text remain self-entered.
- A real map of the venue. The "dungeon map" is a themed path of boss rooms, not floor plans.
- Animations that can't be turned off.

## Interface

Next.js App Router in `apps/web`. Calls the APIs with relative URLs per [000](000-overview.md#http-api), through one typed client `src/lib/api.ts` built on `packages/contracts`. Until the real services land, `NEXT_PUBLIC_FAKE_API=1` switches that client to in-memory fakes with fixture data (a conference, 12 talks, 3 attendees), so the UI is built in parallel.

### Organizer theme studio (addition, 2026-11-09)

Organizers describe the atmosphere and subject of their conference in plain language, for example "an ocean exploration conference: coral chambers, submarine routes, deep-sea bosses". The studio shows a preview of the attendee map and background before the organizer applies the theme. Organizers can revise the description and preview again; canceling leaves the saved theme intact.

Conquest keeps the design system’s frame, typography, component shapes, navigation, and interaction patterns across conferences. Dungeon scenery keeps a consistent pixel-art treatment across themes. The theme changes map scenery, room and boss decoration, theme nouns, palette, and an optional decorative background within that visual system. It does not change the ranked talks, schedule, game rules, or the meaning of accessibility controls. The map remains a dungeon-crawler path rather than a venue floor plan.

Keep text and controls on readable surfaces over any background. Decorative artwork is hidden from assistive technology; the list view carries the same talk data and remains fully usable. The preview includes the list view and reduced-motion behavior.

Dependency: the current `Theme` contract supports palette, nouns and intro only, and there is no theme preview/update endpoint. Before implementing saved map/background customization, coordinate a contract PR with the Game lane that updates `packages/contracts` and `specs/000-overview.md` together. Store structured presentation choices for rendering within the established style. Default to built-in scenery/background presets; generated bitmap artwork is optional future scope. Preview must not save changes; apply must persist the theme on the existing conference. Theme changes preserve attendee progress.

## Behavior

1. **Feedback on every XP action:** after `POST /xp` show the XP gained, the multiplier if any ("Party bonus x1.25"), level-ups and completed quests, announced in an `aria-live="polite"` region.
2. **Map, two views of the same data.** The visual path (SVG or CSS) and a **list view** (ordered list of bosses with time, room, reason, status). The list view is the default when the user prefers reduced motion or turns it on with a toggle, and it is fully usable alone with a screen reader. The visual path is `aria-hidden` only if the list is on the same page.
3. **Step-free routes:** the map marks rooms that aren't step-free (icon + text, never color alone) with the organizer's note, and a toggle "Step-free only" hides bosses in rooms that aren't step-free from the path (they stay in the list, marked).
4. **Accessibility baseline (Merge Forward):** every interactive element reachable and usable by keyboard with a visible focus ring; every image and icon button has alt text or `aria-label`; text contrast ≥ 4.5:1 (the theme is validated by game-api); `prefers-reduced-motion` respected; tap targets ≥ 44 px; form fields have labels; the QR code has its code printed beside it in text; page titles name the page.
5. **Profile photo:** `<input type="file" accept="image/*">` (phones offer camera or library). The browser center-crops to square, resizes to 256x256 and encodes JPEG, lowering quality until it fits 40 KB, before sending. Alternatively, optional LinkedIn sign-in imports the consenting member's name and photo through OpenID Connect, with the photo prepared to the same format server-side. The photo is optional; without one, the class sprite is the avatar. Photos have alt text `<name>'s profile photo`. The LinkedIn field hints "Copy your profile link from LinkedIn (Share profile → Copy link)" and checks the format before submitting.
6. **QR scanning** uses the camera with a typed-code fallback always visible.
7. **Telemetry:** Dash0 browser RUM loaded from `NEXT_PUBLIC_DASH0_RUM_*` (skipped when unset); API calls carry W3C `traceparent` so traces join the services'. No names or typed text in RUM custom attributes.
8. **Demo mode:** `/organizer/[conf]/live?demo=1` and the attendee pages work side by side in one browser window for the split-screen video.

## Acceptance criteria

- **WEB-1** With `NEXT_PUBLIC_FAKE_API=1` every page renders with fixture data and no network calls.
- **WEB-2** The signup flow goes from paste-about to map in at most five taps after typing, prefilling class and suggested goals from `draft`.
- **WEB-3** The map shows bosses in time order with title, time, room and reason, in both the visual and the list view.
- **WEB-4** The list view is on by default when `prefers-reduced-motion: reduce`, and toggleable otherwise.
- **WEB-5** "Step-free only" hides non-step-free bosses from the path and marks them in the list with text, not color alone.
- **WEB-6** Check-in, photo, network and coin actions show the XP gained and the multiplier in an `aria-live` region.
- **WEB-7** The live leaderboard refreshes every 5 s and shows the top 10 with name, class, level and XP.
- **WEB-8** The recap page shows the stats and post, and Copy puts the post on the clipboard.
- **WEB-9** Automated accessibility check (axe via `@axe-core/playwright` or `vitest-axe`) reports no serious or critical violations on `/c/[conf]/map`, `/c/[conf]/join`, `/c/[conf]/boss/[talk]` and `/organizer/[conf]`.
- **WEB-10** Every page is usable by keyboard alone: the signup, check-in and coin flows complete with Tab/Enter/Space only (Playwright test).
- **WEB-11** The QR code always has its code in text beside it, and a typed-code field is always available on the connect page.
- **WEB-12** The theme's palette and nouns are applied on attendee pages (the boss noun appears in the map heading).
- **WEB-13** The organizer page links to the Dash0 dashboard URL from `NEXT_PUBLIC_DASH0_DASHBOARD_URL` (hidden when unset).
- **WEB-15** Signup requires a LinkedIn profile link in a valid format and shows a readable message otherwise; the photo step is optional and a chosen photo is sent as a 256x256 JPEG data URL of at most 40 KB.
- **WEB-16** Avatars (map, leaderboard, allies) show the attendee's photo when set and the class sprite otherwise, always with alt text.
- **WEB-17** The connect page lists allies with a "View on LinkedIn" link that opens their profile in a new tab.
- **WEB-14** API errors show a readable message and never a blank page.
- **WEB-18** The organizer theme studio accepts a description, displays a map/background preview, supports revision, and saves only on Apply; cancel leaves the saved theme unchanged.
- **WEB-19** Applying a theme changes attendee map scenery and the selected background while retaining Conquest typography, component styling, navigation and interactions. The chosen theme survives reload and does not change talk selection or attendee progress.
- **WEB-20** Theme preview and applied themes retain readable text, keyboard access, reduced-motion support, and the accessible map list; backgrounds are decorative and never the only source of information.
- **WEB-21** Signup offers optional LinkedIn OpenID Connect sign-in with only `openid profile` permissions when server credentials, a fixed callback URL, and a cookie secret are configured. When unavailable, manual signup works without contacting LinkedIn.
- **WEB-22** LinkedIn callbacks validate encrypted expiring transaction cookies, state, ID token signature/issuer/audience/expiry/nonce, and matching userinfo subject. Cancelled, expired, invalid, and failed attempts have readable recovery; provider tokens and secrets stay server-side and are not persisted.
- **WEB-23** A successful LinkedIn sign-in returns to the same conference and imports name/photo while preserving typed signup details when tab storage is available. Imported photos use the same 256×256 JPEG/40 KB contract, accept only bounded HTTPS LinkedIn CDN downloads without redirects, and fall back to upload/class art. Missing or invalid import cookies cannot retrieve a profile. Public profile links, headline and about text remain self-entered.
