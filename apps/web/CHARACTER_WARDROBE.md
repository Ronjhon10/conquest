# Photo-based character wardrobe

The character studio is in signup step 2 and `/c/<conference>/profile` (click the avatar on the map). Choose or import a photo, select **Create from my photo**, review the art, try an outfit, and save. Replacing the photo and regenerating do not change the saved character until signup/save succeeds. Existing LinkedIn character recovery applies the reviewed artwork through the existing attendee PATCH route.

`OPENAI_API_KEY` in `apps/web/.env.local` enables server-side image edits. `OPENAI_IMAGE_MODEL` defaults to `gpt-image-2`. The browser receives no API key. Only an explicit creation/regeneration action sends the source photo to OpenAI. Production needs its own runtime key. Missing keys/errors keep a clearly identified default/current character usable. Requests are limited to 43 KB, two concurrent generations and twelve attempts per minute per Web process. Requests time out after three minutes. These limits are for this prototype, not a distributed quota service.

The existing photo contract stores a 256×256 JPEG under 40 KB, marked with COM text `CONQUEST_WARDROBE_V1`. Four 128×128 outfit cells are ordered knight/wizard/rogue/bard. The first cell's 128×48 head pixels are copied to the other three cells before JPEG encoding, guaranteeing the same rendered head across classes; the selected class is a crop, not another generation. Shared Avatar decodes marked art on profiles, maps, leaderboards and allies. Allies have no class in their contract, so they use the first outfit with the same face. Unmarked legacy photos retain their old rendering. No public Game types/routes changed.

Source photos are retained as optional per-attendee local references for same-device regeneration. If browser storage is unavailable or the user changes devices, another source photo can be chosen. The saved wardrobe remains on the attendee. Photographic likeness is generated and must be reviewed by the attendee; pixel locking guarantees consistency between outfits, not perfect resemblance to a photograph.

## Art provenance and prompts

The built-in imagegen tool produced `public/characters/wardrobe-source-v1.png` using `knight-v1.png` as the style/default-person reference. It was copied from the tool output into the project. `public/characters/wardrobe-v1.jpg` and `src/lib/default-wardrobe.json` contain its compact marked wardrobe. Existing class PNGs are preserved for legacy fallbacks. The one live smoke result, `demo/evidence/character-likeness-smoke-v1.jpg`, used fictional knight artwork, not a real attendee photo. Its decoded output was inspected. Tests never call OpenAI.

Final built-in prompt: Create one production-ready 1024x1024 square 2x2 RPG paper-doll outfit sprite sheet. Reference image gives pixel art style and the ONE SAME PERSON used in every cell: exact same dark spiky hair, face, skin tone, age and expression. Four equal 512x512 cells, no gutters, no labels or text or border, uniform flat pale warm grey #eee9dd background throughout. Each cell shows same person in identical front facing full-body standing pose and identical scale, feet near bottom, entire head/hair within the top 176 pixels of each cell, shoulders and all costume details start BELOW y176 relative to each cell. Order top-left KNIGHT slate armor gold shield emblem compact shield; top-right WIZARD indigo robes gold trim short wand held low and book, NO HAT; bottom-left ROGUE charcoal green leather jacket belt utility pouches, compact tools; bottom-right BARD moss green jacket cream scarf small lute held low. All four are conference adventurers with tiny badge lanyard and boots, detailed chunky carefully shaded pixel-art matching reference. Identity and pose absolutely consistent, outfits/equipment only change, no helmets or hoods or accessories covering head. All equipment stays below head region. Isolated sprites centered in each cell, no scenery or UI. Use the reference person as a fictional default avatar, not a photo.

The runtime edit prompt is the exported `CHARACTER_PROMPT` in `src/lib/character-server.ts`: image 1 supplies personal identity, image 2 supplies only the pixel-art treatment and layout. Server code normalizes, locks and marks its output. The generated head's fidelity and the clothing alignment remain reviewable in the preview before persistence.
